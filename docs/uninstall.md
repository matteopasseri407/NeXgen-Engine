# Uninstall

There is no single uninstall command yet. Removal is manual because every write this project makes is a patch to a file you own (see `docs/what-gets-written.md`), not a package installed through a system manager. This walks through undoing each piece.

## 1. Stop the recurring sync (MULTI profile, Linux/systemd only)

This stops the timers and deletes the unit files this project created
under `~/.config/systemd/user/`: the sync guard, the liveness heartbeat, and
the failure-alert template. Nothing outside that folder is touched, and you
can recreate them by rerunning the MULTI setup if you change your mind:

```bash
systemctl --user disable --now agent-sync.timer agent-heartbeat.timer
rm -f ~/.config/systemd/user/agent-sync.service ~/.config/systemd/user/agent-sync.timer \
      ~/.config/systemd/user/agent-heartbeat.service ~/.config/systemd/user/agent-heartbeat.timer \
      ~/.config/systemd/user/agent-alert@.service
systemctl --user daemon-reload
```

If you're on Windows, the MULTI provisioner registers scheduled tasks via
`schtasks.exe` (backed by `03-INFRA/scripts/agent-sync.ps1`) instead of
systemd units. Remove them with:

```powershell
schtasks /Delete /TN "KnowledgeVault Agent Sync" /F
schtasks /Delete /TN "KnowledgeVault Agent Sync Logon" /F
schtasks /Delete /TN "KnowledgeVault Agent Heartbeat" /F
```

## 2. Restore per-CLI config from the backups, or edit by hand

Before `nexgen sync`/`nexgen guard` overwrites a file it manages, it saves the previous version next to it. Two naming conventions are in use, so look for both: the MCP renderer (`nexgen_core/renderer.py`) writes `<file>.bak-<timestamp>` for each per-CLI MCP config, while the guard cycle and the per-CLI permission/guardrail writers write `<file>.pre-<reason>-<timestamp>.bak` for the files they rewrite directly. Look for those next to:

- `~/.claude.json` (the `mcpServers` entries this project added) — `.bak-<timestamp>`
- `~/.codex/` config — `.bak-<timestamp>`
- `opencode.json` (the `instructions` field and its MCP section) — `.bak-<timestamp>`
- `~/.gemini/antigravity/mcp_config.json` — `.bak-<timestamp>`
- `~/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.gemini/config/AGENTS.md` (the instructions pointer) — `.pre-instructions-<timestamp>.bak`
- `~/.claude/settings.json` (checkpoint hook, and the permission posture if your vault declared one) — `.pre-permissions-<timestamp>.bak`

Only the three most recent MCP backups are kept, so the one from before this project first ran may already have been pruned.

If a `.bak` file exists from before this project touched the config, restore it. If not, remove only the MCP entries and the `instructions`/bootstrap pointer this project added; the table in `docs/what-gets-written.md` tells you exactly which field to look at per CLI.

## 3. Remove the bootstrap pointer files

These are the per-CLI bootstrap files this project pointed at its
instructions. Only remove them if you're not also using them for something
else unrelated to this project — deleting one wipes any of your own content
that lived in the same file, not just this project's pointer:

```bash
rm -f ~/CLAUDE.md ~/.codex/AGENTS.md ~/.gemini/config/AGENTS.md
```

## 4. Remove the skill folders this project copied in

There is no fixed list: which skills exist depends entirely on your own
`skills.manifest.yaml` (data, not part of this engine — a fresh install has
none until you add some). Check the catalog, library, and each CLI's runtime folder and
remove only what you recognize as coming from this project's manifest:

```bash
cat ~/.agents/skills/INDEX.md       # managed catalog, not a skill-body root
ls ~/.agents/skill-library           # managed skill bodies
rm -rf ~/.agents/skill-library/<skill-name>
rm -rf ~/.claude/skills/<skill-name> ~/.codex/skills/<skill-name> ~/.gemini/antigravity-cli/skills/<skill-name>
```

`~/.agents/skills/INDEX.md` is regenerated by `nexgen skill index`
(historical name `skills-sync.py --index`).
Do not delete the whole `~/.agents/skills/` folder if another tool uses its
catalog; remove only the managed library folders you recognize.

## 5. Local-Full mode: tear down the local Docker stack

Do this **before** step 6 if you used it — the compose files it needs live
inside the vault clone you are about to delete. If you ran the connectors
on this machine's own Docker (`nexgen stack up`), stopping them
with `nexgen stack down` leaves their data volumes intact, same as the rest
of this project's "repair, never destroy" posture. To actually remove that
data, back up anything you want to keep first (n8n workflows, Firecrawl
data, OCR state), then run `docker compose down -v` yourself inside each
stack's folder under `03-INFRA/deploy/<service>/`.

## 6. Remove the vault clone

**This is the destructive step.** `~/KnowledgeVault` holds both the engine
and everything you've written into it: your notes, your projects, and
`99-INDEX/USER-PROFILE.md`. Deleting it deletes all of that together, and
there is no undo unless you have your own backup or a separate Git remote.
Back up anything under `01-NOTES/`, `02-PROJECTS/`, or `04-NOW/` first if you
want to keep it, then:

```bash
rm -rf ~/KnowledgeVault   # or wherever you cloned it
```

## 7. Cloud-Server mode: tear down the VPS stack separately

If you deployed `03-INFRA/deploy/` (n8n, Firecrawl, OCR) on a VPS, that's a separate Docker Compose stack on a separate machine; this repo's uninstall does not reach it over the network, so you tear it down yourself. Back up anything you want to keep from it first (n8n workflows, Firecrawl data, OCR state) — `docker compose down -v` in that stack's folder deletes its containers *and* its volumes, so that data does not survive the command.

## 8. State and secrets left behind

- `~/.nexgen-engine/`: the machine-local state directory (the sync lock file, the liveness heartbeat timestamp, the doctor's own cache, and the dependency-watch report). Safe to delete, plain text, no secrets.
- `99-SECRETS/`: only relevant if it lived inside the vault clone you removed in step 6. If you copied the GPG archive elsewhere, that copy is untouched by any of the above.
